# Local ecosystem prior art: what the fleet already has that `looks` must consume, not rebuild

*2026-09-02 — research note for the `looks` design phase. Fleet sweep over ~260 local packages under `$PP` (the projects folder), plus 134 Claude session-transcript project directories.*

## Verdict

**`looks` is not the fleet's first ffmpeg wrapper; it is the fleet's first ffmpeg *vocabulary*.** 116 Python files across 27 packages name the `ffmpeg` binary (75 of them outside tests) and build its command lines by hand, and the same five things are implemented between two and five times each: variance-of-Laplacian sharpness (3 shipped implementations, 4 code paths), even-dimension snapping (4 sites, 2 incompatible policies — snap vs. raise), fit/fill/pad geometry (twice: once in moviepy, once as ffmpeg strings), the normalised crop rectangle (3 types, 2 coordinate conventions), and the "is ffmpeg here?" check (26 hand-rolled `shutil.which("ffmpeg")` call sites in 25 non-test files). The single best existing artefact is `muvid.visualize` — its `VisualPlan` + `register_visual` seam is the shape the kickoff already names, but the *reusable* parts are its neighbours: `escape_filter_value` (a correct double-escape for ffmpeg's two-level parser), `require_filter` (per-**filter**, not per-binary, capability checking), `reactive.flash_filter` (`sendcmd`-driven time-varying parameters), and `footage.edl.TRANSITION_CURVES` (a curated 16-of-58 `xfade` vocabulary refused at validation rather than discovered as an ffmpeg error). The measurement tier `looks` needs for its per-source parameter rule already exists, better than anything I would write: `an.bench.metrics` is a pure-numpy panel of twelve *refuted* and several *corrected* image metrics, and it says in writing that Laplacian-family sharpness conflates blur with resolution and that `edge_transition_width` is what separates them. Two things must **not** be extracted: `mixing.video.video_util` is moviepy-through-and-through and has an external consumer the kickoff does not know about (`paces` imports `get_video_dimensions` at four call sites), and `burns` is imported by 15 files across 6 packages and pulls a GPL ffmpeg binary transitively — so `looks` takes a `Rect`-shaped *protocol*, never a `burns` dependency. Finally, the licence thesis is already vindicated inside the fleet: `paces`' ADR-0005 §3 bars ultralytics by name (AGPL-3.0) and `an`'s `tests/test_licence_perimeter.py` enforces a permissive allowlist over installed `dist-info`, while the fleet's *only* existing cartoon stylizer — `paces/docs/poc-reference/tools/stylize.py`, inherited from `kodokan` — is built from three components that cannot ship (ultralytics AGPL-3.0, AnimeGANv2 non-commercial, InsightFace models research-only). The tier is not a hypothesis; it is a rule the fleet has already written in prose and never mechanised.

## 1. Method, and what "verified" means here

Everything below was read from source on 2026-09-02 or measured by running a command. Where I ran something, the command and the observed versions are stated. Anything I inferred but did not execute is marked **unverified** in §10.

- Fleet sweep: `rg` over `$PP` (the projects folder named in the manifest at `$PTH_FILEPATH`, 510 lines / ~260 entries), excluding `.venv`, `node_modules`, and the vendored `misc/pyo` tree.
- Runtime facts: `ffmpeg -version`, `ffmpeg -filters`, `importlib.metadata`, and a small numpy/OpenCV experiment (§4.3).
- Session archaeology: `rg` over `~/.claude/projects/**/*.jsonl` (134 project directories, 2.6 GB).

**Interpreter caution, and it bit me once.** A first run of the §4.3 experiment from the scratchpad resolved `python` to a *different* interpreter reporting `cv2 5.0.0 / numpy 2.5.0`. Re-run from under `$PP` it is `/Users/…/.pyenv/versions/p12/bin/python` with `cv2 4.13.0 / numpy 2.2.6`. Every number in this note is from the second. This is the trap the ecosystem's own instructions warn about; a `looks` doctest that measures anything will hit it too.

## 2. The inventory

Verdicts: **CONSUME** = call it, do not copy it. **EXTRACT** = move it into `looks` and have the current owner import it back. **PORT** = re-derive the *semantics* in `looks`'s own (dependency-free) idiom; the existing code cannot move because of its dependencies. **LEAVE** = out of scope, or too embedded to move.

### 2.5 lookbook, illustration, paces, and the rest

| Where | What it is | Verdict | Why |
|---|---|---|---|
| `lookbook/scorers/technical.py:189-222` — `Blur` | Variance-of-Laplacian with a **numpy-only fallback** when cv2 is absent, and a `config_hash` that is the cache key | **CONSUME the pattern (the cv2-or-numpy fallback), NOT the default** | The `max_side=512` downsample is fine for lookbook's job (ranking within one pool) and **wrong** for `looks`'s (comparing *across sources of different resolution*). ## 3. The duplication ledger — five things implemented N times

This is the concrete case for `looks` existing at all.

### 3.1 Variance-of-Laplacian sharpness: 3 modules, 4 code paths

1. `muvid/footage/scoring/_frame_metrics.py:34` — `cv2.Laplacian(gray, CV_64F).var()`, cv2 lazy-imported. Docstring: *"promotion candidates for `mixing.video` the moment a second consumer appears."*
2. `lookbook/scorers/technical.py:208` — `cv2.Laplacian(gray, CV_32F).var()` **on a ≤512 px downsample**, with (path 3) a numpy `sliding_window_view` 3×3 fallback when cv2 is absent.
3. `illustration/inspection.py:509` — pure-numpy 3×3 via interior finite differences, no cv2, no SciPy.

Plus the Que Calor work's ad-hoc use, which is what the whole per-source scale rule is built on. Four measurements of one quantity, at three different resolutions-of-measurement, with no shared constant. `looks` should host one, keyed by the measurement geometry (see §4.3 for why that key matters), and `an.bench.metrics.edge_transition_width` should sit beside it as the disambiguator.

### 3.2 fit / fill / pad / social: two runtimes, one semantics

| Semantics | moviepy form (`mixing`) | ffmpeg form (`muvid`) |
|---|---|---|
| stretch | `video.resized(new_size=(W,H))` | `scale=W:H` |
| fit (letterbox) | aspect maths + `CompositeVideoClip` over an `ImageClip` background | `scale=W:H:force_original_aspect_ratio=decrease,pad=W:H:(ow-iw)/2:(oh-ih)/2,setsar=1` (`assemble.py:269`) |
| fill (centre-crop) | aspect maths + `.cropped(...)`; **also** `thumbnail.py:_cover_resize` in PIL | `scale=W:H:force_original_aspect_ratio=increase,crop=W:H` (`canvas.py:222`) |
| social (blurred fill) | fit + a second fill pass + PIL `GaussianBlur(15)` + `vfx.MultiplyColor([.7]*3)` | `background_chain` + `cover_chain` + `overlay_chain` (`canvas.py:210-259`) — `gblur=sigma=30`, `eq=brightness=-dim:saturation=…` |

Three implementations of "fill" alone. The ffmpeg form is the one `looks` should own: it is dependency-free, it composes into a larger filtergraph as a *string*, and it is the form the two bounded-memory renderers in the fleet already use.

### 3.3 Even-dimension handling: 4 sites, 2 incompatible policies

- `muvid/footage/assemble.py:65` `_even(n) -> n - n % 2` — **snap down**, silently.
- `mixing/video/_helpers.py:149-150` — **snap down**, inside `_validated_crop_box`.
- `paces/docs/poc-reference/tools/mkclip.py:112-113` — **snap down**.
- `muvid/visualize/video.py:_check_even` — **raise**, with the best error message in the fleet (*"cover art is routinely an odd square (1401×1401, 999×999)… libx264's own error is a long way from the cause"*).

`looks` needs both — an authored size should raise, a derived size should snap — and should name the difference rather than pick one.

### 3.4 The normalised rectangle: 3 types, 2 conventions

- `burns.Rect(x, y, w, h)` — **normalised** fractions, top-left origin, window-fraction zoom. The declared convention.
- `muvid.footage.edl.CropWindow(x, y, w, h)` — **normalised**, explicitly adopting burns' convention "so a crop authored here and a Ken Burns path computed there interoperate with no rename table".
- `paces` `Box = (x, y, w, h)` — **pixels**, ints, with even-snapping (`derivation.py`).

Two of three agreed; the third diverged. `looks` must not add a fourth — take the normalised convention, and treat the pixel form as a rendering of it.

### 3.5 "Is ffmpeg available?": 26 hand-rolled checks, 1 good one

`shutil.which("ffmpeg")` appears bare at **26 call sites in 25 non-test files** (43 sites in 42 files counting tests) — `braidio` alone has six modules doing it (`sources`, `music`, `multivoice`, `weave`, `conversation`, `render`), plus `foley/weave/master.py`, `falaw/local.py`, `paces/derivation.py`, `reelee-web/e2e/capture/`, `burns/misc/`, `mixing/transcript/media.py`, and more. Only `muvid.visualize.ffmpeg` checks for the *filter* rather than the binary — which §4.1 shows is the check that actually matters on this machine. `mixing.util.ffmpeg_exe()` is the one that prefers the bundled binary. Across the fleet, 116 files (75 outside tests) name the `ffmpeg` binary; by package (all files): `an` 22, `muvid` 17, `paces` 11, `mixing` 8, `braidio` 6, `nw` 5, `yb`/`ge`/`foley` 4 each.

This is the strongest possible argument for `require_filter`: "shell out to ffmpeg" does not mean "ffmpeg's documented feature set is available", and the difference is not knowable at install time.

### 4.2 Timeline support is a per-filter fact, and it decides whether `Effect.at` is expressible

`ffmpeg -filters`'s flag column answers "can this filter carry an `enable='between(t,a,b)'` expression?". Measured on the system 8.1:

| Filter | Flags | Timeline (`enable=`)? |
|---|---|---|
| `lut3d`, `haldclut`, `lutrgb`, `curves`, `colorchannelmixer`, `colorlevels`, `colorspace`, `deband`, `pseudocolor`, `unsharp`, `gblur`, `geq` | `TS` | **yes** |
| `eq`, `hue`, `edgedetect` | `T.` | **yes** (no slice threading) |
| `tonemap` | `.S` | no |
| `xfade` | `.S` | no |
| `elbg`, `palettegen`, `zoompan` | `..` | **no** |

So the Que Calor chain's ffmpeg half (`lut3d` → `lutrgb`) is fully timeline-gateable — an `Effect.at` on it compiles to `enable=`. A posterise via `elbg` (ffmpeg's own ELBG-algorithm posterizer, an alternative to the `lutrgb` quantiser) is **not**, and neither is `zoompan`. `looks` should derive this per effect at registration time, from `ffmpeg -filters`, the same way `has_filter` already does.

**The flag column changed between 7.1 and 8.1.** ffmpeg 7.1's legend is three flags (`T..` timeline, `.S.` slice threading, `..C` command support); 8.1's legend is **two** — the "Command support" column is gone from `-filters` output. Consequence: `sendcmd`-controllability (the mechanism `muvid.visualize.reactive` depends on) is no longer discoverable from `-filters` on 8.1. Any parser of that output must split on whitespace and take field 1, never slice fixed columns; `muvid`'s `_available_filters` already does.

### 4.3 Laplacian variance is not scale-invariant, and lookbook's docstring overstates its case

`lookbook/scorers/technical.py:_to_grayscale_array` downsamples to `max_side=512` and says this is *"without materially changing blur / exposure measurements"*. Measured (`cv2 4.13.0`, `numpy 2.2.6`, `Pillow 11.3.0`; two 1536×1536 synthetic images — low-frequency structure plus Gaussian texture at two amplitudes; `cv2.Laplacian(..., CV_32F).var()`):

| image | 1536 (full) | 1024 | 512 | 256 |
|---|---|---|---|---|
| sharp / textured | 9684.8 (1.000) | 2143.0 (0.221) | 541.2 (**0.056**) | 136.4 (0.014) |
| soft | 219.4 (1.000) | 51.0 (0.232) | 14.4 (**0.066**) | 6.2 (0.028) |

Two conclusions. The absolute value drops ~18× from 1536 to 512, so a number measured after downsampling is not comparable to one measured at source resolution. And the *ratio* differs between the two images (0.056 vs 0.066), so it is not even a constant rescale — meaning rank order can move, not just magnitude. For lookbook's job (rank one pool, all measured the same way) the claim is harmless. For `looks`'s job — comparing post-effect sharpness *across sources of different resolution* to land them in family, which is the kickoff's central measured rule — it is not. **The measurement geometry must be part of the metric's identity** (and therefore part of its `config_hash`).

### 4.4 The redistribution chain, confirmed by inspection

`burns 0.0.9` declares `moviepy`, `numpy`, `pillow`. `moviepy 2.2.1` declares `imageio_ffmpeg>=0.2.0`. `imageio-ffmpeg 0.6.0` ships a binary at `…/imageio_ffmpeg/binaries/ffmpeg-macos-aarch64-v7.1` whose `-version` reports `--enable-gpl --enable-libx264 --enable-libx265`. So `pip install burns` does redistribute a GPL-built ffmpeg with GPL-licensed encoders, exactly as the kickoff states — and `mixing` additionally *prefers* that binary at runtime (`mixing/util.py:26-55`). `looks` must depend on none of `burns`, `mixing`, or `moviepy`.

Also present and importable in the shared environment, as the kickoff says: `av 16.0.1` and `ultralytics 8.4.75`. Licence spot-check of candidate `looks` dependencies (from installed `dist-info`): `argh 0.31.3` → **LGPL** (classifier: *GNU Library or Lesser General Public License*) — so a `looks` CLI should use `typer 0.19.2` (MIT) or stdlib `argparse`, **not** `argh`, even though `lacing`, `illustration` and `muvid` all declare it. `click 8.4.2` BSD-3-Clause, `pillow 11.3.0` MIT-CMU, `opencv-contrib-python 4.13.0.92` Apache-2.0, `opencv-python-headless 4.13.0.92` Apache-2.0, `pydantic 2.12.2` MIT, `dol 0.3.65` MIT, `xdol 0.1.12` Apache-2.0, `numpy 2.2.6` BSD-3-Clause.

## 6. Two independent derivations of the same execution shape

Worth recording because it settles the kickoff's first exclusion with evidence rather than assertion.

`muvid/footage/assemble.py` (2026, after 30-cut OOM kills on a 3.7 GB box): render **one intermediate per part** with a single decoder, concat by stream copy via the concat demuxer, mux the audio in the final pass. Memory O(1) in cut count. Its docstring: *"Reaching for one filtergraph over all parts is exactly how the OOM below comes back."*

`~/Downloads/que_calor/work/style/render_v2c.py` (2026-09-02, independently): split into 8-second chunks, stylise each in a `ProcessPoolExecutor` worker through a decode-pipe/encode-pipe pair, write a `list.txt`, `-f concat -safe 0 -c copy`, then mux the source audio. It additionally pins `-x264-params keyint=15:min-keyint=15:scenecut=0 -video_track_timescale 90000` so the chunks are concat-by-copy compatible — a detail `assemble.py` handles differently and which `looks` should *not* own either way.

Two teams, two problems, same answer. A convenience `looks.render(clip, look)` would be a third derivation waiting to happen, and it would get it wrong.

There is also a boundary lesson in `render_v2c`. `stylise_chunk` reads the **EDL** (`_spans`, `_clip_at`) to decide which per-clip mean-shift parameters apply at output time *t*. So the strongest measured argument for `looks`'s design — parameters resolve against the clip they apply to — is simultaneously the case where a look must *consult* the cut list without owning it. `muvid.footage.edl` owns the EDL. `looks` needs `Effect.at` to be a span plus a resolver, and to take the span *from* whoever owns the cuts.

## 8. Decisions the sweep forces, that the kickoff leaves open

1. **"Zero dependencies" needs a precise reading.** The kickoff says both "zero hard *media* dependencies" and "`pyproject.toml` declares nothing but stdlib". Those differ. `xdol.Registry` (Apache-2.0, pure Python, and whose `tags`/`keys_with_tag`/`search(tags=…)` is a ready-made licence-tier query) costs four pure-Python permissive packages and no binaries. Recommendation: **state the rule as "no dependency that links or redistributes a codec, and no copyleft"**, then decide `xdol` on its merits. If the answer is stdlib-only, port ~150 lines and say why in the module docstring.
2. **`burns` stays separate — the census settles it.** 15 importing files across `mixing`, `illustration`, `walkthru`, `reelee`, `tw_platform` and tests. `looks` takes a structural `Rect` (`.x/.y/.w/.h`, normalised, top-left origin) and never defines its own. If an ffmpeg geometry fast-path is wanted, it belongs in `looks` as a *compiler from* a `BurnsPath`-shaped object, registered into `burns.RENDER_BACKENDS` by whoever wires them — and it should use `crop=` with a `t`-ramp, not `zoompan` (§2.1, §4.2).
3. **`looks` should own normalisation as well as stylization** (the kickoff's second open question). Three converging pieces of evidence: `tonematch.py` and `mklut_b.py` bake the continuity grade and the extreme look into **one** `.cube`; both compile to the same `-vf` insertion point; and both are governed by the same per-source resolution rule. One vocabulary, two intents, and the intent is a tag on the effect rather than a different type.
4. **The licence tier needs three states, not two.** `illustration.licensing`'s invariant is the model: an unrecognised code **survives unchanged and therefore fails the gate** — unknown is refusal. Its recorded failure mode is the one to fear: *"the failure direction is invisible (fewer hits, no error)."* Every tier decision in `looks` must be observable in the returned object, not merely in what is missing from it.
5. **Effects need an execution-kind, not just a backend name.** Three kinds exist in the fleet (§5): ffmpeg-filter-string, raw-frame pipe, pre-rendered path. They differ in whether `Effect.at` compiles to `enable=` (kind 1 only, and only for timeline-capable filters), whether they can be fused into a neighbour's chain (kind 1 only), and what they cost. `VisualPlan` models kinds 1 and 3; kind 2 is new.

## 10. Explicitly unverified

Marked so no downstream reader treats these as established.

- **`cv2.stylization`'s boundary behaviour.** `paces`/`kodokan`'s POC uses `cv2.stylization(sigma_s=60, sigma_r=0.45)` at half resolution. It is in OpenCV's `photo` (non-photorealistic rendering) module, the same family as `edgePreservingFilter`, which the Que Calor work measured as smearing across object boundaries. Whether it exhibits the same defect at those parameters is **unverified** — I did not run it.
- **`elbg` as a posterise alternative.** Present in ffmpeg 8.1 (*"Apply posterize effect, using the ELBG algorithm"*), no timeline support. I have not compared its output or cost to the `lutrgb=r='trunc(val/N)*N+N/2'` quantiser the Que Calor chain uses.
- **AnimeGANv2 / White-box Cartoonization / InsightFace licence texts.** I took the kickoff's statement that AnimeGANv2 and White-box Cartoonization are non-commercial as given, and my InsightFace claim ("model packs research-only") is from general knowledge, not from reading a `LICENSE` file in this session. All three need the *text* checked before they appear in a `looks` tier table — the rule `reelee-web`'s licence guard enforces (the licence text is the authority, the metadata field is not) and `an`'s perimeter test records (the PyPI `dssim` trap) applies here.
- **`opencv-python` version reporting.** `importlib.metadata` reports `opencv-python 4.12.0.88` while `cv2.__version__` is `4.13.0` and `opencv-contrib-python` reports `4.13.0.92` — consistent with two `cv2`-providing distributions being installed, which `mixing`'s pyproject comment warns about. Not load-bearing here; flagged because it will confuse someone.
- **Whether `yb` would break.** `yb` imports `muvid.visualize` symbols (`CoverLayout`, `PathLike`, `render_audio_video`, `visuals.Visual`). None of the extraction items #1-#8 move those *names*, but I did not run `yb`'s suite.
- **Any claim about ffmpeg on Linux or the server.** Every ffmpeg fact in §4 is macOS/arm64, Homebrew 8.1 vs `imageio-ffmpeg` 0.6.0's bundled 7.1. The filter sets will differ elsewhere — which is itself the argument for `require_filter`.
